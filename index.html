Layered Capability Map

按工作层级组织，而不是按工具堆砌。

每一类能力都对应真实协作场景：理解、修改、验证、交付。你描述目标，Codex 负责把它落到文件、命令、浏览器和文档里。

01

代码与工程

围绕代码库做判断、编辑和验证。

  • 阅读项目结构、入口、配置与依赖
  • 实现功能、修复缺陷、控制改动范围
  • 运行测试、构建、静态检查
  • 代码审查，指出风险与缺失验证
  • Git 分支、暂存、提交与 PR 协助 工程闭环
02

本地工作区

直接围绕你的电脑和当前目录工作。

  • 快速检索文件、文本、类型与配置
  • 读取终端输出，执行必要命令
  • 理解现有环境和依赖路径
  • 尊重未提交改动，避免误删用户工作
  • 把结果落到真实文件 同机协作
03

浏览器与前端验证

从代码实现推进到可见体验。

  • 打开本地页面或开发服务器
  • 检查响应式布局和文本溢出
  • 点击、输入、滚动，验证交互路径
  • 截图比对视觉状态
  • 发现问题后继续迭代 视觉 QA
04

文档与办公

把工作成果转成可阅读、可交付的文件。

  • 创建、读取、修改 Word 文档
  • 提取、合并、处理 PDF 内容
  • 制作和调整演示文稿
  • 清洗、生成、分析电子表格
  • 渲染检查版式质量 办公交付
05

多模态创作

让视觉资产进入实际项目。

  • 生成插图、纹理、海报和界面素材
  • 编辑已有图片，调整风格或内容
  • 识别图片内容，辅助设计决策
  • 结合网页、演示和文档使用
  • 输出可复用的视觉方向 图像能力
06

自动化与长期任务

把一次性协作延伸成持续跟进。

  • 设置提醒、后续检查和定时任务
  • 监控变化并主动回到线程
  • 周期性运行工作区任务
  • 保存清晰、自包含的任务说明
  • 适合重复检查和长期维护 持续执行
07

插件与技能

按专业场景调用更窄、更强的工作流。

  • 使用技能处理图片、文档、表格和演示
  • 通过插件接入浏览器和桌面能力
  • 复用项目或团队沉淀的流程规范
  • 发现、安装和创建新的技能
  • 让能力随工作场景扩展 可扩展

Verified Workflow

从一句需求，到一组经过验证的结果。

Codex 的价值不在于“多写一点”，而在于持续对齐目标、限制改动范围，并用实际检查证明结果可用。

1

理解目标

先读上下文和项目现状，明确成功标准、约束和可能的取舍。

2

制定方案

选择最小可行路径，避免无关重构，把任务拆成可以验证的步骤。

3

执行修改

编辑真实文件、运行命令、接入需要的工具，让方案进入可运行状态。

4

验证交付

测试、构建、浏览器检查或文档渲染后，给出清楚的结果说明。

Connected Workspace

Codex 连接的是整个工作现场。

它可以在同一个线程里切换角色：工程搭档、前端质检、文档编辑、自动化助理，或是插件化的专用专家。

一个协作入口，多种执行表面

对用户来说，只需要描述“想完成什么”。对 Codex 来说，任务会被映射到代码、终端、浏览器、文件、图像、文档和自动化系统。

输入目标、文件、截图、现有代码、口头偏好
过程探索、计划、实现、检查、迭代
输出网页、补丁、文档、表格、图片、任务结果

Terminal

运行命令、读取输出、验证构建与测试结果。

Browser

打开本地页面，检查视觉、响应式和交互状态。

Documents

处理 Word、PDF、PPT、表格等办公交付物。

Image

生成和编辑视觉素材，辅助网页和内容创作。

Automation

创建提醒、周期任务和持续监控。

Skills

按专业场景加载更精确的工作流程。

Start with intent

直接说目标，Codex 会把它拆成能执行、能验证、能交付的工作。

例如：做一个网页、修复一个 bug、审查一段代码、整理一份报告、生成一张视觉图，或设置一个后续提醒。
